## B1 (blocking) — EvolveGCN training bug invalidates Exp 2 and the Exp 5 temporal ablation

`ml/temporal/train.py::train_one_epoch` (EvolveGCN branch) detaches `w1, w2` at
every window boundary (`w1 = w1.detach()`). From the second window on, no
gradient reaches `initial_w1/initial_w2`. They are trained only on the first
window (steps 1–5, illicit rate ~1%).

- With `evolve=False` ("frozen" ablation), `initial_w*` *are* the model, so it is
  effectively trained on 5 near-empty snapshots → PR-AUC 0.079 (≈ chance). A frozen
  EvolveGCN is architecturally a static 2-layer GCN and should land near GCN
  (0.62 on paper_refit). The gap is a bug, not a finding.
- With `evolve=True`, the starting weights come from the same 5 steps, then are
  rolled forward ~35 steps. ROC-AUC 0.58 ± 0.29 (some seeds below 0.5) is consistent
  with this, not with "weight drift because nodes don't persist".

**Fix**
1. Train with full BPTT over the whole training sequence (one backward per epoch
   over all train snapshots; 34 small snapshots fit easily in memory), or keep
   windows but carry *non-detached* weights for gradient to `initial_w*` (i.e. do
   not use truncation for the -O variant). Keep `clip_grad_norm_`.
2. Add tests in `tests/test_temporal.py`:
   - after one epoch on ≥2 windows' worth of synthetic snapshots, the loss on the
     **last** snapshot produces a non-zero gradient on `initial_w1`;
   - `EvolveGCNO(evolve=False)` and a static 2-layer GCN with the same init give the
     same logits on one snapshot.
3. **Sanity gate before reporting anything:** on paper_refit, frozen EvolveGCN must
   be within the block-bootstrap CI of static GCN. If not, there is still a bug.
4. Re-run EvolveGCN (all splits, both feature sets, 5 seeds) and the Exp 5 temporal
   row. Regenerate exp2/exp3/exp5 tables and figures. Archive the old runs in
   `experiments/results/_archive/`.

## B4 — Explanation exports are partly broken (found while building UI mockups)

Checked all 80 files in `data/processed/explanations/`:
- **Fidelity is 0.00 in 61/80** (`fidelity_plus` non-zero in only 19, `fidelity_minus` in 5).
  Investigate `ml/explainability/gnn_explain.py` (likely the explainer is run on a
  model/config where the masked prediction equals the original, e.g. wrong
  `model_config.return_type`, threshold config, or explaining the wrong node index:
  note `node_idx` 182377 is global while `explainer_edges` use period-local indices).
  Add a test on the synthetic graph that a planted, decisive edge gets fidelity+ > 0.
  The UI must show low/zero-fidelity explanations as "not reliable", not hide that.
- **Mixed models in one explanation:** every file has `model_run_id: "xgb_gcn_paper_refit_all"`.
  `score`, `threshold` and `top_features` (SHAP) come from XGBoost, while
  `neighbor_contributions` and `explainer_edges` come from the GCN. Store per-model
  explanations (`<model_run_id>/<txId>.json`), each explaining its own score, and
  include the GCN's own score/threshold in the GCN explanation.
- **Wrong pattern flag:** 106364923 has `high_illicit_neighborhood`, but its 1-hop
  neighbours are licit (0.004) and unknown (0.100), and its 2-hop set is 21 licit /
  27 unknown, 0 illicit. Define each flag precisely in code + docstring, compute it
  from labels/scores of the right model with an explicit cut-off, and unit-test it.
